## Archived

[archive/](archive/) holds historical records: completed feature slices,
superseded designs, and one-off research. They are kept for context and are
**not** maintained — see [archive/README.md](archive/README.md) for the index
and the reason each document was retired.

Nothing in `archive/` should be cited as current behaviour. When you change
behaviour that an archived document describes, update the live document
instead; only touch the archive to add a closing note.

## Conventions

- **Live docs have stable names** (`architecture.md`, `backlog.md`, …) and are
  updated in place. **Archive docs keep their original dated names**
  (`2026-10-04_files_attachment_lane.md`) because the date is part of the
  record.
- **Record a decision where it is made.** A feature's rationale lives with the
  feature doc; the closing slice that implemented it goes to the archive.
- **Update the doc in the same commit as the code.** A doc that describes
  behaviour the code no longer has is worse than no doc.
- `AGENTS.md` holds the *rules*; the `docs/` tree holds the *reference*. If a
  rule and a reference disagree, the rule wins and the reference is a bug.
