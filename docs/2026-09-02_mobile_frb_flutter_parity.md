- **Bulk peer-stats aggregation replaces the per-peer N×3 queries** (this task): `mobile_api::get_peers_with_stats` was doing one `get_peer_stats` per known peer (N×3 DB queries). New shared `messages::get_all_peer_stats() -> Result<HashMap<peer_id, PeerMessageStats>, …>` computes stats for **all** peers in a single `GROUP BY` query (un-nesting each DM against both its sender and recipient via `UNION ALL`, so a DM counts toward both peers just like `get_peer_stats`), plus one read of the persisted `broadcasts_sent` counters from the `peers` table (`broadcast_sent` has no aggregate column). Implemented with a `QueryableByName` `PeerMessageAggregate` row + one `peers_table.select((peer_id, broadcasts_sent))`. `get_peers_with_stats` now loads the map once and looks up each peer (`.map_or(0, …)` for peers with no messages), so the call is 2 queries regardless of peer count.
