# Themes: dark/light + accent color (2026-11-21)

> **ARCHIVED** — a historical record of completed work, kept for context.
> It is not maintained and may describe behaviour that no longer exists.
> Current documentation: [docs/architecture.md](../architecture.md),
> [docs/README.md](../README.md).

This closes **US-025** (dark/light theme) and **US-026** (custom color scheme).
A single persisted choice drives both the TUI and the Flutter/web frontend.
Rust owns the palette, so no color value or valid accent name is duplicated in
Dart — the frontends only render the resolved snapshot Rust hands them.

## Canonical model

`src/theme.rs` owns everything:

- **`Accent`** is a newtype over an index into a private canonical table of six
  swatches: `teal` (the default, matching the original Flutter seed), `blue`,
  `violet`, `rose`, `amber`, `green`. An arbitrary string can never be an
  `Accent` — `Accent::parse` validates before any write, so an invalid state is
  unrepresentable. `Accent::next()` wraps for the TUI cycle shortcut.
- **`AppTheme`** is the snapshot returned to frontends in one round trip:
  `dark`, `accentName`, the resolved `accentArgb` seed, and the full list of
  `AccentOption` swatches. The swatch list travels with the snapshot so a
  frontend renders exactly the options Rust accepts.
- **`Palette`** (behind the `tui` feature) maps the choice to concrete ratatui
  colours: the accent for tabs and unread banners, and contrasting
  selection/popup backgrounds for dark vs light.

## Persistence

The theme reuses the generic `app_settings` table introduced for LAN-only mode.
`src/settings.rs` adds typed `theme_dark()` / `theme_accent()` readers and
`set_theme_dark` / `set_theme_accent` writers; dark defaults to `true` and the
accent to `teal`, so existing installs keep their look. `theme::set(dark, name)`
validates the accent *before* writing either key, so a bogus value cannot leave
the two settings out of sync. Reads are best-effort, like the other settings.

## Frontend surface

Both transports expose `getTheme` / `setTheme` through `NodeApi` (in-process
FRB, HTTP/WS for web, and the test fake). The web JSON dispatch mirrors the FRB
names and carries drift guards for the no-param and params-required cases.

- **TUI**: Settings shows `Theme: dark/light / accent`; `t` toggles dark/light
  and `c` cycles the accent. Both persist through `theme::set` and update the
  in-memory palette so the next frame reflects the change (a DB error surfaces
  as a popup). Renderers take the `Palette` from `TuiRenderState`, so the tab
  bar, chat headers and selection highlights follow the choice.
- **Flutter/web**: a root `themeNotifier` (loaded before `runApp`) makes
  `P2pApp` a `StatefulWidget` that rebuilds the whole `MaterialApp` on a theme
  change. The seed colour is always Rust's `accentArgb`, and `themeMode` follows
  the `dark` flag (never `system`, so the persisted choice is authoritative).
  The Settings "Theme" card offers a dark toggle and the Rust-provided swatches;
  Dart only renders them and forwards the chosen name.
