## Done items

- **Broadcast-stats rework: `broadcast_recipients` table replaces `broadcast_received` + the dormant `peers.broadcasts_sent` aggregate** (this task, uncommitted→commit): unified the "Broadcast" column on **broadcasts *we* sent to each peer**, dropping the inverse inbound (`broadcast_received`-from-peer) semantics. New table `broadcast_recipients(id, msg_id, peer_id, sent_at, confirmed_at)` is minted in a Diesel migration `2026-09-02-000000_broadcast_recipients` and hand-maintained in the FRB-ignored `src/generated/schema.rs` (`diesel::table!` + `allow_tables_to_appear_in_same_query!`). `peers::record_broadcast_recipients(msg_id, peer_ids)` (renamed from `record_broadcasts_sent`, now per-message/per-peer with `sent_at`, idempotent `on_conflict((msg_id,peer_id)).do_nothing()` so retransmits can't double-count) is called at send time from `mobile_node::save_outgoing_broadcast` and the **TUI** `send_message` broadcast path (peers from `state.connected.connected_peer_ids()`). `messages::save_receipt` back-fills `confirmed_at` on a kind-0 (ack) receipt so confirmed not just transmitted broadcasts can be attributed. `PeerMessageStats`/`PeerWithStats`/`get_peer_stats`/`get_all_peer_stats` now surface `broadcast_sent_to_peer` (count from the new table) instead of `broadcast_received`; the `GroupBy` un-nesting (`UNION ALL` over DM sender+recipient) plus one grouped `count(*)` over `broadcast_recipients` stays 2 queries. The `(msg_id, peer_id)` pair is passed by clone into the swarm/DB both paths. Dropped `broadcast_received` from `mobile_api::PeerWithStats`, `PeerMessageStats`, the Flutter orphan `messages.dart` class (`broadcastSentToPeer`), and `main.dart`'s `_broadcastCount`/`_refreshPeers`; both frontends' peer-table "Broadcast" column now means broadcasts-sent-to-peer. `TuiRenderState`/`AppState` gained `broadcast_sent_to_peer` (refreshed in `AppState::resort_peers` via a bulk call; no longer a `VecDeque<Option<String>>` passed through `tui_helpers::sort_peers_table`/`peer_table_rows_range`, which now take `&HashMap<String, usize>` with `#[allow(clippy::implicit_hasher)]`). Unit tests updated (`get_all_peer_stats...` now asserts `broadcast_sent_to_peer` for the new table; TUI helpers pass a sent-to map; `it can` no longer references `broadcast_received`).
